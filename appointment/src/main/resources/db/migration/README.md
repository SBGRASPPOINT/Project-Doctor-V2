# Migrations live here once Flyway is enabled

This directory is the destination for the baseline schema, but it is intentionally **empty of
SQL**: the current schema is generated by Hibernate from the `@Entity` classes
(`spring.jpa.hibernate.ddl-auto=${DDL_AUTO:update}`), and a hand-written baseline would be a
guess that drifts from the entities.

To adopt versioned migrations:

1. Boot the app once against a throwaway PostgreSQL database.
2. Run `./scripts/dump-schema.sh` — it writes `V1__baseline.sql` from that database.
3. Add the Flyway dependency (`implementation("org.flywaydb:flyway-database-postgresql")` plus
   `flyway-core`), set `DDL_AUTO=validate`, and delete the throwaway database.
4. From then on, every schema change is a new `V<n>__*.sql` file reviewed in a pull request.

Until then, `ddl-auto=update` never drops, renames or back-fills anything, so a schema change
that needs data to be migrated (a new NOT NULL column on `appointments`, say) has to be applied
by hand.
